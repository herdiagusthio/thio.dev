# thio.dev

Astro 7 static site — Herdi Agusthio's personal engineering console (blog, case studies, ADRs, live agent office). Output is plain HTML served by Caddy from `/var/www/thio.dev` on a VPS; no server runtime. See README.md for routes and commands.

## Commands

- `npm run build` / `npm run dev` run `scripts/sync-content.mjs` first, which mirrors `../second-brain` (or `$SECOND_BRAIN_DIR`) into `content/` and **deletes** `content/**/*.md` not public in the source. It fails if the source is missing; without second-brain use `SECOND_BRAIN_DIR=fixtures/second-brain`. `content/` is generated and git-ignored. `npm run build` also chains `node scripts/verify-csp.mjs` after `astro build` as a fail-closed CSP gate over `src/**/*.astro` and `dist/**/*.html`. Use `npx astro build` to build without touching `content/`.
- `npm run check` (astro check) and `npm test` (node:test over `scripts/*.test.mjs`, `src/**/*.test.ts`) must stay green; CI runs both plus the build from `fixtures/second-brain`, and fails if a `PRIVATE-FIXTURE` sample reaches `dist/`. CI never deploys — `./ship.sh` on the VPS does, then runs `scripts/smoke-check.sh` (every sitemap page returns 200 live, and the live homepage is byte-identical to `dist/index.html`).

## Content pipeline

- Privacy boundary = the sync allowlist (`isPublic` in `scripts/sync-content.mjs`): frontmatter `status: published` (blog, engineering) or `accepted|superseded` (decisions), and decisions must be numbered ADRs (`NNN-*.md`) — the agent pipeline's `sdlc-*`/`goai-*` tickets in `decisions/` never sync, whatever status they carry. Everything synced is published, so keep it fail-closed; `fixtures/second-brain` holds a private sample of each kind that CI keeps out of `dist/`.
- Infrastructure: the sync rewrites `content/infrastructure.json` (generated) from `infrastructure/catalog.json` via `sanitizeCatalogForPublic`, field by field from an allowlist. `visibility: public` = full card, `internal` = name/purpose/stack only, anything else private; never IPs, paths, kernel, tables or columns. Missing catalog = empty projection; malformed = the sync throws. Free text (names, titles, purposes, stacks, categories, engines, summaries) of public and internal apps is author-trusted and published as written: the scrub that drops IPs, ports, paths, URIs and emails is defense in depth only (bare internal hostnames can't be told from prose), so keep secrets and internal hosts out of those fields in second-brain. `src/pages/infrastructure.astro` reads it through `import.meta.glob`, so a build without it renders an empty page.
- Quality gate = `src/content.config.ts` (glob-loader collections, strict schema: `title`, `date` YYYY-MM-DD, `tags` ≥1, `status`; blog and engineering also need `summary` ≥40 chars, ADRs fall back to their Context paragraph). Optional: `lang` (`en`|`id`, put on an article's title/lead/body — the site chrome stays English) and `featured` (homepage case studies). Fix bad frontmatter in second-brain, not in `content/`.
- `src/lib/content.ts` `getEntries(kind)` is the only content API (view model + per-kind summary fallback); pure helpers live in `src/lib/text.ts` so node:test can import them without `astro:*`.
- Markdown uses Astro's Satteri processor with an mdast plugin dropping the body's first H1 (`astro.config.mjs`); smart punctuation and syntax highlighting are off on purpose.
- Routes: `blog/[slug]` ← blog, `showcase/[slug]` ← engineering, `decisions/[slug]` ← decisions (index at `/decisions`); all render through `src/layouts/ArticleLayout.astro`. Every page uses `src/layouts/BaseLayout.astro`. Merged/removed slugs keep working through `redirects` in `astro.config.mjs`; a redirect source must stay unpublished in second-brain, or the redirect shadows the real page.

## Office page

- `src/scripts/office.ts` (bundled module) renders the 2D office; identity comes from `src/data/agents.ts` (single roster, also used by /about), state only from the same-origin live API `/api/public/office` (Caddy proxies it to vps-dashboard), validated by `normalizeSnapshot` in `src/scripts/office-data.ts`. Nothing is invented when the API is down: agents stay `Unknown` and the HUD says telemetry offline. The API's `pipeline` (AI-DLC stage + ticket counts) and per-agent `lastActive` are rendered with `textContent`.
- All HTML built from data must go through the `html` tag in `office-data.ts` (escapes every interpolation); colors are hex-validated because they land in `style`; `id`/`state` must be identifiers. Clicks use `data-agent-id` delegation — no inline handlers.
- The 3D bundle writes agent labels with `textContent`; its toolbar icons need the matching `#i-<name>` symbols in the sprite in `office.astro` (copied from vps-dashboard's `public/index.html`).
- Local runs have no `/api/public/office`, so they show the telemetry-offline state; mock `fetch` to test live mode.
- `public/js/office3d.bundle.js` is prebuilt from `../vps-dashboard` (`bun run build:3d`); `office.ts` loads it on the first switch to 3D (`load3D`). The dossier is a native `<dialog>`. `public/k8s/index.html` is a standalone game.

## Config

- `site` in `astro.config.mjs` (override `SITE_URL`) is the single origin: canonicals, JSON-LD, sitemap, RSS and the office API host derive from it. Canonical URLs have no trailing slash; the sitemap and RSS match.
- Fonts are self-hosted from `src/assets/fonts` (Astro `fonts` config, local provider, OFL licenses alongside); `<Font>` in `SeoHead.astro` defines `--font-sans`/`--font-mono`. No third-party requests at build or run time.
- Content-Security-Policy: `astro.config.mjs` enables Astro 7's `security.csp` (`CSP_DIRECTIVES` + `extractK8sScriptHash()` from `scripts/verify-csp.mjs`), emitting `<meta http-equiv="content-security-policy">` in `<head>`; standalone `public/k8s/index.html` carries its own hashed `<meta http-equiv="content-security-policy">` policy with `data-*` delegated click listeners. `node scripts/verify-csp.mjs` fails the build on `<script is:inline>`, unhoisted executable scripts, `'unsafe-inline'`/`'unsafe-eval'` in `script-src`, unhashed inline scripts, or inline `on*=` attributes, and prints the canonical Caddy header.
